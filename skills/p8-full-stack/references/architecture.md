# 全栈架构与跨切面（选型 / API / DB / 鉴权 / 部署 / 测试策略）

本篇提供贯穿前后端的**跨切面视角**，是单一技术栈视角不具备的整合增值。用于技术选型、架构设计、
API 契约、数据层、鉴权、部署与测试策略的权衡判断。

## 1. 技术选型框架

按四因素决策，不盲追新：
- **团队栈与人才**：团队熟 Java → Spring Boot；熟 TS → NestJS；高并发网关 → Go。
- **场景与规模**：强事务中大型业务 → Spring Boot/JPA；轻量/AI 接口 → FastAPI；同构全栈 BFF → NestJS。
- **生态与运维**：语言工具链成熟度、可观测性、招聘成本。
- **演进成本**：迁移/重写风险与收益（参考 uniapp 迁移清单的渐进策略）。

> 选型结论须给出 trade-off 与推荐，并标注撤销条件（何时该换）。

## 2. API 设计契约

- **REST 约定**：资源命名复数、HTTP 动词语义、状态码规范（2xx 成功 / 4xx 客户端 / 5xx 服务端）。
- **版本**：路径 `/api/v1` 或 Header；破坏性变更升版本。
- **统一响应**：`{code,msg,data}` 信封（前端 Element Plus 对齐）。
- **分页**：`{records,total,page,size}`（与前端、小程序一致）。见 `backend-multilang.md` §4。
- **幂等**：写操作带幂等键或唯一约束，防重复提交（支付/下单关键）。
- **文档**：OpenAPI/Swagger 先行，契约即文档。

## 3. 数据层

- **关系型**：规范范式、外键与索引（高频查询列/联合索引）；事务边界在 service 层（`@Transactional`/显式 tx）。
- **N+1 防范**：JPA `@EntityGraph`/批量抓取；ORM 明确懒/急加载。
- **何时 NoSQL**：高写入/灵活 schema（文档、KV、时序）才引入；不为了"现代化"滥用。
- **迁移与回滚**：Schema 变更可向后兼容（加列而非改列）；有回滚预案。

## 4. 鉴权与授权

- **方案选型**：会话（有状态，易撤销）vs JWT（无状态，注意过期与吊销）vs OAuth2/OIDC（第三方/SSO）。
- **密码**：BCrypt/Argon2 哈希；禁止明文/MD5/SHA1。
- **RBAC/ABAC**：角色/属性级授权；接口方法级校验（`@PreAuthorize`/守卫）。
- **令牌**：JWT 密钥存配置/环境变量，不进代码；前端**不**存明文 Token 于可泄露处。
- **越权防御**：接口必须校验资源归属，不信任前端传入的 ID/角色（呼应 quality-gates 安全红线）。

## 5. 部署与渐进式发布

- **CI/CD**：构建 → 单测（含 `-race`/覆盖率门禁）→ 静态扫描 → 制品 → 灰度。
- **发布策略**：蓝绿 / 金丝雀（灰度）+ 回滚预写；**回滚未就绪不得发布**。
- **可观测**：结构化日志 + traceId + 关键 metrics + 告警；错误监控与转化漏斗（小程序见 analytics）。
- **环境隔离**：dev/test/prod 分离；配置外部化，密钥走秘密存储。

## 6. 测试策略（测试金字塔）

- **单元（基底，强制）**：纯函数/算法/业务逻辑，见 `go-testing.md` / 各栈测试基线；目标关键 100%/公共 90%/一般 80%。
- **集成**：真实 DB（Testcontainers/内存库）、消息、外部依赖打桩。
- **端到端**：关键用户路径（登录→下单→支付）；有 UI 须真人功能验证（见 quality-gates）。
- **测试数据**：隔离、可重置；不污染生产数据。
- **回归基线**：每次改动跑既有测试，无新增失败方可交付。

## 7. 跨栈一致性

- 前后端共享错误码与分页结构；DTO 隔离实体（防越权/泄漏）。
- 统一命名与目录规范（前端见 frontend-spec，后端见 backend-multilang/go-backend）。
- 同一业务术语在需求、API、DB、UI 保持一致（避免"订单/order/dingdan"混乱）。
- 任何跨栈改动：先评估双方影响面，再按各自栈门禁验证。
