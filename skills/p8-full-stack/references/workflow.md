# 统一工作流细则（从 SKILL.md §三 展开）

本文件是 `p8-full-stack` 的**流程执行手册**。所有步骤以 SKILL.md 的七步闭环为权威，本文件给出
可操作的判定与动作细节。

## 1. 档位 → 最小执行集

| 档位 | 触发判定 | 必须动作 | 可豁免 |
|------|----------|----------|--------|
| **轻量** | ≤1 文件 + ≤1 步 + 非安全 + 纯查询/小改/纯文案 | 实码确认（Read+冲突检查）+ ≥1 条真实证据 + 一行收尾 | 免 routing、规划门禁、三池、复盘记忆 |
| **常规** | 明确、单模块、低风险 | 最小"需求→步骤"映射 + 引用点实码确认 + 精简自检 | 免三池、仅打命中项 |
| **复杂** | 多文件/跨模块/DB·配置·构建链/安全权限/批量/业务不明 | 方案先行 + 影响面(2跳上游) + 全量清单 + 收尾报告 + 复盘记忆 | 无（全量） |

> 判据以本表为唯一源；**只定策略，不替代路由**。

## 2. 规划门禁（PLAN-GATE，复杂档）

改前按三池打勾（A 无条件核心 / B 条件触发，未命中写 N/A / C 规模触发），并过规划自审：
- **占位符**：计划中无 `TODO`/`XXX` 等未填项。
- **签名一致**：函数名、接口名、文件名在计划与实码一致。
- **需求→步骤映射**：每条需求都能追到具体步骤。
- **引用点实码 trace**：计划中的引用（调用点/文件）在仓库中真实存在。

## 3. 影响面与实码确认

- 改模块前查 **2 跳上游**调用者，上游一并改并验；结论须独立 `grep` 复核（不可逆操作不单凭图谱）。
- 实码确认三件套：`Read` 目标文件 + 冲突检查（轻量档仅此二项）+ `Grep`（涉函数/符号签名改动时须全仓搜）。
- **架构一致性铁律**：同构（范式唯一 / 对称契约同源 / 半迁移=0）。
- **批量 7 防线**：同操作 ≥3 文件或 ≥10 处启用；批量子任务链式执行，每 5 文件 CHECKPOINT。

## 4. 打磨环（反复打磨，强制）

见 SKILL.md §三 Step 4。落地要点：
- 单轮只改一个维度，改完复验（re-run 相关测试/构建）再进下一轮。
- 收敛判据：每维度连续两轮无新增改动，或达用户约定验收标准。
- 打磨轮次与每轮改动须可追溯（写入交付说明或交接检查点）。

## 5. 失败升级与收敛

- 同因重复失败且无新信息 → 换取证路径（不同工具/不同入口/最小复现）。
- 达上限 → 列 2–3 方案（标推荐项 + 已/未验证），计数写入交接/计划。
- 资源/权限/必要信息确实缺失 → 保存可执行交接（已完成部分 + 缺失条件 + 可直接接续下一步）。
- 轮次：默认 3 轮 / 安全最大 6 轮（仅约束单 Wave）。

## 6. 长任务可靠性（L0）

- 每 Wave 或 5 原子任务落 `.ai-memory/handoff.md` 检查点：已完成带证据 / 相关文件 / 未完成 / 阻塞。
- 子 Agent 边界：检索型只返 `文件:行号 + 原文`；执行型经授权复核后落码；审查型只出清单。
- 委派前须输出目标 / 边界 / 口径。

## 7. 未验证项强制披露（L0）

无法验证 / 降级 / 部分失败须列入「已知限制 / 未验证项 / 部分失败明细」，不得写成全部完成。
