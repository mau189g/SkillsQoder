# 质量门禁清单（从 SKILL.md §五 展开）

验证阶段（Step 5）按以下清单逐项打勾。**任一 ❌ 回 Step 3 修复。** 任一命中项缺失证据视为未完成。

## A. 清单化质量自审（10 条）

1. ☐ **功能完整**：需求 → 实现逐项对应，无遗漏分支。
2. ☐ **真实证据**：至少一类证据（命令+退出码 / 用例数+通过数 / 截图+步骤 / Status+Body）。
3. ☐ **单元测试**：含业务逻辑/算法/纯函数的代码有配套单测，且跑通。
4. ☐ **边界覆盖**：空值、极值、异常、并发、幂等均有处理或测试。
5. ☐ **契约对称**：写入 key == 读取 key（两态等式）；无新旧混用残留。
6. ☐ **调用方枚举**：改动影响的所有调用方已同步并更新。
7. ☐ **静态扫描**：`go vet`/ESLint/TS strict 等对应工具零新增报错。
8. ☐ **构建通过**：目标构建（按技术栈）成功。
9. ☐ **回归基线**：同模块无新增失败（跑既有测试）。
10. ☐ **打磨收敛**：经五维打磨（正确性/可读性/健壮性/性能/安全）且可追溯。

## B. 安全红线（10 条）

1. ☐ **无 SQL/命令注入**：参数化查询；不拼接用户输入进 SQL/shell。
2. ☐ **无 XSS**：用户输入输出均转义/消毒；不 `v-html` 未可信内容。
3. ☐ **无越权**：接口做权限/归属校验；不信任前端传入的 ID/角色。
4. ☐ **无密钥明文**：密钥/Token 不进代码、不进前端、不进日志。
5. ☐ **输入校验**：所有外部输入在边界校验（binding/validator/schema）。
6. ☐ **CSRF/重放**：敏感写操作有 token/签名/幂等保护。
7. ☐ **依赖安全**：新增依赖先审查（许可证/已知漏洞/真实版本）。
8. ☐ **最小权限**：DB/文件/API 凭据按最小权限配置。
9. ☐ **敏感数据**：隐私数据不落日志、不明文存储、脱敏展示。
10. ☐ **不可逆操作保护**：删除/覆盖/迁移有备份、确认、回滚预案。

## C. 证据类型速查

| 变更类型 | 有效证据 |
|----------|----------|
| 配置/文案/静态 | 实际文件或产物核对；影响运行行为时补真实入口 |
| 纯函数/算法 | 真实调用 + 独立期望 + 边界与反例；不能只断言"未报错" |
| API/业务流程 | 实际请求、响应、必要状态变化，明确服务与数据库环境 |
| 页面/应用 | 启动并到达目标页、执行相关操作；视觉与交互分别核对 |
| 构建/部署 | 构建、制品、启动、功能结果分别记录 |
| 迁移/并发 | 新旧路径及多方契约、重复/并发/失败恢复 |

> 本门禁统一了质量自审与后端/前端安全红线，作为 Step 5 验证的强制清单。
